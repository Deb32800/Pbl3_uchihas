NavPark: A Predictive Parking Solution

System Architecture Document

Introduction
The Smart Parking Navigation System for Hong Kong is designed to address urban congestion and inefficient parking discovery. The system helps drivers locate available parking spots in real-time and suggests optimal navigation routes based on traffic conditions and user preferences. This architecture document outlines the structural design and deployment strategy that supports the core functionality of the application.
Architecture Goals
Performance
The system must provide fast and responsive services, including real-time updates of parking availability and route suggestions, even under heavy traffic and data load in densely populated areas like Hong Kong.
Security
All components of the system must ensure secure communication, data encryption (in-transit and at-rest), and protection against unauthorized access to safeguard user credentials, sensor data, and server resources.
Safety
The system promotes user and public safety by providing accurate, real-time data that helps reduce unnecessary driving and distractions. Design decisions prioritize minimizing risks related to navigation errors or misleading parking information.
Availability
The system must remain operational and accessible at all times, with high uptime and minimal disruption. Redundant components and cloud infrastructure are used to support failover and continuous availability.
Maintainability
The architecture must support ease of maintenance and future upgrades. Modular components and clearly defined APIs allow developers to fix bugs, add features, or replace services with minimal impact on the overall system.
Architecture Tier
The system architecture for the Smart Parking Navigation system is organized into three main tiers: the Presentation Tier (User Interface), the Application Tier (Backend Services), and the Data Tier (Database & Storage). Additionally, the architecture includes external APIs such as mapping services and real-time traffic data providers.

Client Server Architecture

Client Interface Description of Client Associated Server Description of Server
Login / Registration Interface for user sign-up and login. Sends an HTTP request with user credentials. User Server Handles authentication and stores account info in the User Account Database. Sends HTTP responses with tokens.
Parking Map Interface Interface that displays real-time parking availability on a map. Parking Data Server Fetches and processes live parking data from external sources (e.g., HK Gov API). Sends color-coded availability data.
Prediction Display Interface that shows forecasted parking availability for the next 1–2 hours. Prediction Server Runs a machine learning model using historical data to generate predictions
Navigation Interface Allows users to get directions to a selected parking lot using turn-by-turn routing. Routing Server Uses Google Maps API to calculate and send optimized routes, traffic-aware ETA, and rerouting instructions.
Feedback Interface for submitting feedback and viewing user reviews for parking lots. Feedback Server Collects, stores, and manages feedback and ratings. Connects to Parking Lot DB and User DB for context.

Pipe and Filter

Figure: Pipe and Filter Architecture Diagram

NavPark streamlines smart parking navigation through a structured pipe-and-filter workflow. The process begins when a user submits a start point and destination (User Request). The system validates preferences (e.g., parking cost, walking distance) via the User Database, then calculates the initial route and ETA using the Map Service. The Traffic Prediction Filter refines the path based on the traffic prediction model to avoid congestion, while the Parking Prediction Filter identifies available spots based on the parking prediction model. The Recommendation Filter further personalizes options. The system then builds the Navigation Plan, which triggers the Notification Filter to send confirmations and alerts. Finally, the Map Render Filter displays the complete navigation solution with directions on the map interface.
